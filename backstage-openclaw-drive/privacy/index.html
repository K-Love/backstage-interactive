Privacy draft

Draft date: November 7, 2026. This is not the privacy policy in effect. The website policy remains the Privacy Policy for backstageinteractive.com. This page is only a draft about a private tool.

The facts below were supplied for this draft on November 7, 2026. The DigitalOcean server and the Google account were not inspected while the page was written. Where a fact was not supplied, the page says it is not established. It does not fill the gap with a promise.

Who operates the app

The OAuth app name is Backstage OpenClaw Drive. I, Kevin Love, operate it as Backstage Interactive. It is a private tool for my own use. It is not a public product on the website.

I am not the operator of OpenClaw in general. OpenClaw is the software this tool runs. This draft is about this app only.

What this draft covers

This draft is about the private Drive tool described on the app draft. It does not cover the website contact forms, KeyProse, WildThesis, or a client site.

The website forms and this tool are different. The forms on the studio homepage, Website Fixes, and the Google Business Profile page collect the notes described in the website Privacy Policy. Those forms do not request Google Drive. Sending a form does not authorize this app, and authorizing this app does not send a website form.

Drive access now

A dedicated Google account has authorized Drive access for this app. This draft does not publish that account, and it does not publish a password or a client secret.

The permission was described as broad. The exact scope strings were not supplied. This draft does not name scopes, because a guessed name would be false precision.

The connector is configured for a folder named Backstage Work. That is a configuration choice on the tool. It is not the same fact as the Google permission. This draft does not say Google enforces a folder-only sandbox, and it does not say the broad permission is limited to that folder by the provider.

What was tested

One upload test passed, and one download test passed. This draft does not name the file, list metadata fields, or say whether that test file is still in the folder. Those details were not supplied.

Automatic transfers of Drive files are not implemented. Bringing Drive files into Chief’s workflow is not implemented. That is a statement of what is absent, not a roadmap.

Server and other services

OpenClaw runs on a DigitalOcean server. Daily backups of that server are enabled. Restoring from a backup has not been tested. This draft does not say what the backup copies, how long a backup is kept, or whether a backup can be wiped on request.

OpenClaw uses Abacus for model requests. It uses Telegram for conversations with me. Drive file content going to Abacus or Telegram has not been demonstrated. This draft does not convert that gap into a promise that file content never goes there, and it does not claim the opposite. What those services receive from this app is not established.

The website itself is hosted on Netlify. That host is described in the website Privacy Policy. This draft does not move the private tool onto Netlify, and it does not say Netlify stores Drive files.

What is not established

A complete retention and deletion policy is not established. That includes working copies of files, logs, server backups, and copies a provider may hold. No time period is stated.

No statement is made here that data is not stored, not shared, encrypted, or excluded from model training. Those promises were not supported by supplied facts.

No Limited Use sentence is made. Google’s Workspace user-data policy asks apps that use the relevant scopes to say, in substance, that use of information received from Google Workspace scopes adheres to the Google User Data Policy, including the Limited Use requirements. This draft does not say that. The scopes, the providers, and the retention rules are not verified. Saying it now would claim a practice this page cannot show.

This draft is not an assurance that Google will approve the app, and it is not legal advice. The documents a later review would have to face include the OAuth 2.0 policies (opens in a new tab), the Google API Services User Data Policy (opens in a new tab), and the Workspace user data and developer policy (opens in a new tab). Linking them is not a claim of compliance.

Revoking Google access

Removing the app’s Google permission, or revoking it from the Google account, stops further API access with that permission. It does not automatically delete copies that may already exist on the DigitalOcean server, in a daily backup, or with Abacus, Telegram, or another provider. Whether any of those copies exist, and how to delete them, is part of the retention gap above.

Questions about this draft

Use the contact form on the studio homepage. Say that the note is about the Backstage OpenClaw Drive privacy draft. That form is a website form. It collects the name, email, topic, and note described in the website Privacy Policy. It does not connect to Google Drive.

This site does not publish an email address, a phone number, or a street address. This draft does not add one. A support email shown to a Google user is an open decision, listed below. Until that decision is made, the homepage form is the only public contact path.

Decisions required before publication

This list is why the page is still a draft. Publishing it, or pasting its URL into an OAuth consent screen, should wait until these are answered in words that can be checked.

  1. Exact scopes and data. The scope strings Google shows, and a plain-language list of which Drive data the app can read or change. “Broad permission” and “configured for the Backstage Work folder” are not those strings, and they are not a provider-enforced folder limit.
  2. Working copies and logs. Where a file is written when the tool uses it, where logs are written, and whether a test file or its metadata is kept.
  3. Retention, deletion, and backups. How long working files, logs, and daily server backups are kept, what a backup contains, whether restore works, and how a person gets a copy deleted. Revoking Google access is not that policy.
  4. Providers, processing, and training. Whether Abacus, Telegram, or any other provider receives Drive file content, names, or other Drive data, and whether any of it is used to train a model.
  5. Support email. Whether a user-support email will be published for this app. The website’s public contact remains the homepage form. No address is invented here. Google’s consent screen commonly displays a support email; that value is not chosen in this draft.

There is no separate terms page for this app. The website Terms of Use still cover the website only. A terms page for the tool is not added here, because the tool is private and the open privacy facts above are the blocking gap.
